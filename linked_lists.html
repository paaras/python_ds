Loose nodes are hard to manage

  • Last week we linked nodes by hand, with one variable per node
  • To add a node at the end, you have to know which variable holds the last node
  • With 100 nodes you would need 100 variables

  

  

  
We want something that keeps track of the nodes for us







  
A LinkedList only needs to remember the head

  

    
    
      
  • If you have the first node, you can reach every other node by following next
    • 
      
  • So the LinkedList stores only a reference to the first node, called head
    •

An empty list has head = None

  

    
    
      
  • A new LinkedList has no nodes, so head points to nothing
    • 
      
  • Almost every method has to handle this case first, usually with if self.head is None:

Traversal: visiting every node

  
    
    
  • Start at the head and follow next until you reach None
    • 
    
  • current does the moving. self.head stays on the first node the whole time.
    • 
  

  







  
Moving head instead of current loses the list

  
    
    
  • This version prints the same values, but it uses self.head as the moving variable
    • 
    
  • A node that nothing points to is gone. Python frees its memory.
    • 
  

  







  
Counting the nodes

  
    
    
  • The same traversal, with a counter that goes up once per node
    • 
    
  • Try an empty list. The loop never runs and count stays 0.
    • 
  

  

  







  
Adding to the front (prepend)

  
    
    
  • Point the new node at the current first node, then point head at the new node
    • 
    
  • Two assignments, no matter how long the list is
    • 
    
  • On an empty list, new_node.next becomes None, which is correct. No special case needed.
    • 
  

  

  







  
Watch Out!

  
    
    
  • If head moves first, nothing points to the old first node anymore
    • 
    
  • Then new_node.next = self.head makes the new node point at itself
    • 
  

  

  







  
Adding to the end (append)

  
    
    
  • Walk to the last node, the one whose next is None, then attach the new node
    • 
    
  • The loop checks current.next so it stops on the last node. Checking current would walk past it to None.
    • 
    
  • An empty list has no last node, so the new node becomes the head
    • 
  

  

  







  
Searching for a value

  
    
    
  • Visit each node and compare its data with the target
    • 
    
  • Return True as soon as you find it. If current reaches None, the value is not in the list.
    • 
  

  

  







  
Inserting at a position

  
    
    
  • Walk to the node before the position, then link the new node in
    • 
    
  • Link the new node to the rest of the list first, then attach it. This is the same order rule as prepend.
    • 
    
  • Index 0 has no node before it, so it uses prepend
    • 
    
  • An index past the end prints a message and leaves the list alone
    • 
  

  

  







  
Removing the first node

  
    
    
  • Move head to the second node
    • 
    
  • Once the method returns, nothing points to the old first node, so Python frees it
    • 
    
  • An empty list has nothing to remove, so print a message and return
    • 
  

  

  







  
Removing a value

  
    
    
  • To skip a node, change the next of the node before it with prev.next = current.next
    • 
    
  • So the loop keeps two variables, with prev one step behind current
    • 
    
  • If the target is the first node there is no prev. Move head instead.
    • 
    
  • If current reaches None, the value is not in the list
    • 
  

  

  







  
Edge Cases

  
    
    
  • An empty list, a list with one node, a change to the first node, a change to the last node
    • 
    
  • Most linked list bugs only show up in one of these cases
    •

Counting steps

  
    
    
  • Time complexity describes how the number of steps grows as the list grows
    • 
    
  • n is the number of nodes, and here a step is one line of code run
    • 
    
  • A method that walks the list takes more steps on a longer list. A method that only touches head takes the same steps every time.
    •

Space complexity: O(n)

  
    
    
  • Every item needs its own node, and every node stores two things, data and next
    • 
    
  • n items take n nodes, so memory grows in a straight line with n
    • 
    
  • The methods themselves use O(1) extra space. current, prev and new_node are a few variables, however long the list is.
    • 
  

  

  

  







  
Keeping a tail reference

  
    
    
  • Store self.tail as well, pointing at the last node
    • 
    
  • append no longer needs to walk, so it goes from O(n) to O(1)
    • 
    
  • The cost is that every method that changes the last node now has to keep self.tail correct, including prepend on an empty list and remove of the last node
    •
