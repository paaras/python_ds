From trees to graphs

A tree node has two pointers, left and right, and we reach every node by starting at the root. A graph has fewer rules. A node can be connected to any number of other nodes, there is no root, and the connections can form a loop.

Nodes and edges

A graph is made of nodes and edges. An edge connects two nodes, and two nodes that share an edge are called neighbors. Click any node to see its neighbors.

What graphs are used for

Anything made of things and the connections between them can be stored as a graph

Maps

Cities are nodes and roads are edges

Friends

People are nodes and friendships are edges

Websites

Pages are nodes and links are edges

Directed and undirected

In an undirected graph an edge goes both ways. If Ana is friends with Ben, then Ben is friends with Ana. In a directed graph an edge only goes one way, like following someone. Ana can follow Ben without Ben following her back.

The graphs in the rest of these slides are undirected

Storing a graph

We need to store which nodes are connected. We use a dictionary where each node is a key and its value is a list of its neighbors. This is called an adjacency list. Click a node to see its list.

The dictionary

The Graph class

A Tree only remembered its root. A Graph has no root, so it remembers every node in a dictionary called neighbors. A new graph has no nodes yet, so the dictionary starts empty.

add_node gives a new node an empty list. add_edge adds each node to the other one's list, because the edge goes both ways.

A node here is only a name like "A", so we don't need a Node class

Visiting every node

  
In a tree we visited every node by going left and right from the root, and we never came back to a node we had already seen. A graph can have loops, so following edges can bring us back to where we started. Step through this code to see what goes wrong.

  







  
Remembering where we've been

  

    

      
To fix this we remember every node we've visited, and we only go to a neighbor if we haven't visited it yet.

      
We keep the visited nodes in a set. A set is like a list with no duplicates, but checking if something is in a set takes O(1) and checking a list takes O(n).

      
There are two common ways to visit every node, depth-first search and breadth-first search. Both use visited, and the only difference between them is the order they visit the nodes in.

    

    

      
Using a set

      

    

  







  
Depth-first search

  
Depth-first search, or DFS, follows one path as far as it can before trying another. From each node it moves to the first neighbor it hasn't visited. When a node has no unvisited neighbors left, it goes back one node and tries the next neighbor there.

  

  

  
Order visited

  







  
Depth-first search: code

  
dfs_from adds the node to visited, prints it, then calls itself on each neighbor that isn't in visited. We don't write any code for going back. When a call finishes we return to the call that made it, and that call checks its next neighbor.

Breadth-first search

  
Breadth-first search, or BFS, visits the nodes closest to the start first. It visits the start, then every neighbor of the start, then every node that is two edges away, and so on. Each of these groups is called a level.

  

  

  
Order visited

  







  
Breadth-first search: code

  
BFS uses a queue. We remove the node at the front, print it, and add its unvisited neighbors to the back. Nodes that were added first come out first, so a whole level is printed before the next one starts. A neighbor goes into visited as soon as it's added to the queue so it can't be added twice.

  
current nodewaiting in the queueprinted

  

  
The queue is a list to keep the code short. pop(0) is O(n), so our linked list queue would be faster.







  
DFS vs BFS

  
Both searches visit every node once, but in a different order. DFS follows one path as far as it goes and BFS spreads out one level at a time. Click a node to start from there.

A stack and a queue

  
The order comes from where each search keeps the nodes it still has to come back to. DFS keeps them on the call stack, and a stack gives back the newest item first, so DFS always continues from the node it reached last. BFS keeps them in a queue, and a queue gives back the oldest item first, so BFS finishes the closer nodes before it moves on.

Graphs in more than one piece

  
A graph doesn't have to be connected. If we start at A in this graph, DFS and BFS never reach X or Y because no edge leads to them. To visit every node we go through every key in the dictionary and start a search from each one that hasn't been visited.

  







  
Time complexity

  
n is the number of nodes and e is the number of edges. Two graphs with the same number of nodes can have very different numbers of edges, so we need both to describe how long a search takes.

  

    
MethodTimeWhy

    
      
add_nodeO(1)Adds one key to the dictionary

      
add_edgeO(1)Adds one item to the end of two lists

      
dfsO(n + e)Visits every node once, and checks every edge twice, once from each end

      
bfsO(n + e)Does the same work as dfs in a different order

    
  

  
Our graph has 7 nodes and 8 edges. Both searches printed 7 nodes and checked 16 neighbors, 2 for each edge.







  
Space complexity

  
The graph takes O(n + e) space because the dictionary has one key for every node and every edge is stored in two lists. visited can end up holding every node, so it takes O(n) in both searches.

  
DFS also needs the call stack and BFS needs the queue. How big they get depends on the shape of the graph, but neither one can hold more than n nodes, so both are O(n).

Summary

  

    
    
      
  • A graph is nodes connected by edges, with no root and no rule about where a node goes
    • 
      
  • We store it as a dictionary where each node has a list of its neighbors
    • 
      
  • A graph can have loops, so DFS and BFS keep a visited set and never go to a node twice
    • 
      
  • DFS follows one path as far as it can, then goes back. It uses recursion, so the call stack remembers the way back.
    • 
      
  • BFS uses a queue to visit one level at a time, so it reaches every node using the fewest edges
    • 
      
  • If the graph isn't connected, one search only reaches the nodes in the same piece as the start
    •
